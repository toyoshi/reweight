# フィードを19本に拡充し、Telegram配信を計画した

## フィードの見直し

MVPでは NHK・朝日・日経の3紙と、はてなブックマーク3カテゴリの計6フィードで動かしていた。元気がでる記事の候補は十分に集まっていたが、ソースが全国紙に偏っていた。地方発の改善ニュースを拾えていない。

そこで地方紙のRSSを調査した。北日本新聞（富山）と熊本日日新聞がRSSを公開していたので追加した。テレビ局（テレビ東京HD、テレビ朝日）や自治体サイト（熊本市、名取市、岩国市教育委員会）、内閣府のフィードも候補に挙がったが、プレスリリースやIR開示、教育イベント中心のものは元気がでるニュースの判定に適さない。絞り込んだ結果、地方紙2紙を残した。

## はてなブックマークの全カテゴリ展開

はてなブックマークは、人が注目した記事が集まるという点でRSSフィードの中でも特殊なソースだ。人間のフィルタリングを一段噛ませた情報源といえる。

MVPでは人気エントリーの「世の中」「政治と経済」「学び」の3カテゴリだけだった。これを全7カテゴリ × 人気エントリー・新着エントリーの14フィードに拡充した。

```
学び / おもしろ / エンタメ / 暮らし / 政治と経済 / 世の中 / 総合
× 人気エントリー + 新着エントリー = 14フィード
```

「おもしろ」や「エンタメ」から元気がでる記事が出るかはわからない。だが、LLMのスコアリングで弾けるのだから、入り口は広くしておいて問題ない。量を増やしても判定の質が落ちないのはLLMベースの強みだ。

## Telegram配信の計画

Markdownファイルを出力して終わり、では配信にならない。将来的にはメールで届けたいが、まずはTelegramで自分宛に投稿する仕組みをつくることにした。

設計方針はこうだ。

- 外部gemを追加せず、Ruby標準の`net/http`でTelegram Bot APIを叩く
- 記事ごとに1メッセージ送信する（Telegramの4096文字制限を回避しつつ、モバイルで読みやすい）
- HTML parse modeを使う（TelegramのMarkdownモードはエスケープが面倒）
- 既存のMarkdownファイル出力はそのまま残す
- `TELEGRAM_BOT_TOKEN`が未設定なら自動でスキップ

## わかったこと

**フィードは増やしても安全だ。** LLMのスコアリングがフィルタとして機能するので、入り口を広げてもノイズは増えない。むしろソースの多様性が上がることで、全国紙が拾わない地方の改善事例を見つけられる可能性がある。

**はてなブックマークのサブカテゴリRSSは存在しない。** はてなブログ（一般）のような細分化されたページにはRSSが用意されていなかった（404）。カテゴリ単位が最小粒度。

**配信手段は段階的に増やすのが正解だ。** メール配信の仕組みを一気に作ると、登録フォーム・オプトイン・配信停止・計測と、やることが膨大になる。まず自分一人がTelegramで受け取る形を先に動かして、コンテンツの質を毎日確認できる状態をつくる。
