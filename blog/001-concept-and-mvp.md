# ニュースの「重み付け」を再設計する ── Reweight というプロダクトをつくり始めた

## 世界は良くなっているのに、そう感じられない

児童死亡率は下がり続けている。識字率は上がっている。極度の貧困は減っている。

データを見れば、世界は確実に前進している。しかし日々のニュースを追っていると、そうは感じられない。事件、災害、対立、不安。目に入る情報の大半はネガティブなものだ。

これはメディアが悪いという話ではない。人間の注意は脅威に引き寄せられるようにできていて、情報の流通構造がそれを増幅しているだけだ。構造的な問題だ。

だから、構造で対処することにした。

## Reweight ── 情報重み付けの再設計

Reweight は「ポジティブニュース」ではない。

楽観を届けたいわけでもない。やりたいのは、情報の重み付けを再調整すること。世界が実際に前進した事実を、適切な頻度で届けること。目的は希望ではなく、認知の精度を上げることだ。

具体的には、こういう基準で記事を選ぶ。

**採用する記事:**
- 問題が解決に向かっている
- 数値的な改善が確認できる
- 再現性のある取り組みである
- 社会的な進展がある

**採用しない記事:**
- 単なる感動話・美談
- 不幸の裏返し構造（悲劇があったからこそ生まれた話）
- 扇情的なタイトルに依存している
- 根拠不明の楽観論

「良いニュース」を集めるのではなく、「前進の事実」だけを抽出する。この違いが重要だと思っている。

## MVPをつくった

コンセプトは固まった。次は動くものをつくる番だ。

最小のプロダクトとして、ニュースRSSを巡回し、「前進」に該当する記事を3件選んで要約し、メルマガの本文をMarkdownで出力するCLIツールをつくった。

技術スタックはシンプルにした。

- Ruby
- feedjira（RSS取得）
- OpenAI API / GPT-4o（前進判定 + 要約生成）

処理の流れは4ステップ。

```
RSSフィード取得 → 前進判定（スコアリング） → 要約生成 → Markdown出力
```

### 前進判定

全記事に対して GPT-4o で0〜100のスコアをつける。プロンプトには上記の採用/不採用基準をそのまま組み込んだ。上位3件を選定する。

### 要約生成

選ばれた3件について、元記事の転載ではなく独自の要約を生成する。事実ベースで2〜3文。

### 出力

Markdownファイルとして日付つきで保存する。将来的にはこれをメール配信する想定だ。

## 最初の実行結果

初回実行で77件の記事を取得し、スコアリングした結果、選ばれた3件はこうだった。

**1. 徳島市の26年度予算案1231億円　小学校給食費無償化や防災強化**

徳島市が小学校の給食費無償化と防災強化に予算を充てる。教育の負担軽減と市民の安全性向上。具体的な施策で、数値も明確。これは「前進」だ。

**2. 公共工事の賃金基準4.5%アップ　初の平均2万5千円超**

公共工事における労働者の賃金基準が引き上げられた。4.5%という数値改善があり、労働環境の改善に直結する。

**3. 食道がんの温存治療後、禁酒禁煙で新たながんリスク8割減**

京大などの研究成果。禁酒禁煙でリスクが80%減少するという、再現性のあるエビデンス。

77件中、85点以上がついたのは6件。そのうちの上位3件。感覚的にも妥当な選定だと思う。逆に、事件・事故・訃報・スポーツ結果は軒並み低スコアで弾かれた。判定基準がうまく機能している。

## わかったこと

**LLMの判定精度は実用レベルにある。** origin.md に書いた採用/不採用条件をプロンプトに落とし込むだけで、かなり的確に前進記事を識別できた。ルールベースでは到底実現できない判定が、自然言語の指示だけで動く。

**RSSだけでも十分な記事数が集まる。** 3フィードで77件。前進記事の候補が足りなくなることはなさそうだ。

**コンセプトの言語化が判定精度に直結する。** 「ポジティブなニュース」ではなく「前進の事実」という基準設計が、判定の質を決めている。感動話や美談を弾けているのは、不採用条件を明確に定義したからだ。
